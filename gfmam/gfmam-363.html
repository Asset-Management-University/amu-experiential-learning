Why this matters

This is the course where a reported figure stops being trusted by default. You will compute the reliability metrics everybody quotes and interrogate the definitions behind them, because a correctly calculated 94 per cent can still describe a plant that is not reliable; model system reliability rather than multiplying component numbers; decide, on evidence, what actually matters and what spares it needs; set operating limits and build a maintenance strategy grounded in the machine in front of you; report performance in a form somebody uses on Monday; and run root cause analysis that reaches the condition rather than the person, so the same three machines stop failing and being investigated separately each time. It is the largest course in this qualification, and what changes for you is that you leave able to ask what a number actually means before you act on it.

Where this begins
Availability is reported at 94 per cent every month and the plant is not reliable. The number is true - it is computed correctly from the definitions the site agreed years ago, which count planned outages as available and exclude anything under two hours. Underneath it, the same three machines fail repeatedly, the spares for them are not held, nobody has decided which of them actually matters, and each failure is investigated as a separate event by somebody who was not there for the last one.

What you will be able to do
By the end of this module you can compute reliability metrics that mean what they appear to mean, model system reliability rather than component availability, decide what is critical, hold the right spares, set operating limits, build maintenance strategies grounded in the machine, report performance somebody uses, and find causes that recur rather than events that repeat.
